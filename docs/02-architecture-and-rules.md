# 架構契約、麻將規則與 P2P 協議規格 (02-architecture-and-rules.md)

本文件定義 `mj` 專案的跨模組邊界、144 張麻將編碼、台灣 16 張麻將確定性狀態機、台數計算規則與 P2P 防作弊訊息契約。所有 Subagent 實作時必須嚴格遵守本文件之型別與索引定義。

---

## 1. 144 張麻將牌編碼規格 (`TileKind` & `TileId`)

- **`TileKind` (`u8`: `0..=41`，共 42 種牌面)**：
  - **萬子 (Characters, `0..=8`)**：一萬 (`0`) ～ 九萬 (`8`)，每種 4 張（共 36 張）
  - **筒子 (Dots, `9..=17`)**：一筒 (`9`) ～ 九筒 (`17`)，每種 4 張（共 36 張）
  - **條子/索子 (Bamboos, `18..=26`)**：一條 (`18`) ～ 九條 (`26`)，每種 4 張（共 36 張）
  - **風牌 (Winds, `27..=30`)**：東 (`27`)、南 (`28`)、西 (`29`)、北 (`30`)，每種 4 張（共 16 張）
  - **三元牌 (Dragons, `31..=33`)**：中 (`31`)、發 (`32`)、白 (`33`)，每種 4 張（共 12 張）
  - **花牌 (Flowers, `34..=41`)**：
    - 四季：春 (`34`, `1花`)、夏 (`35`, `2花`)、秋 (`36`, `3花`)、冬 (`37`, `4花`)，各 1 張
    - 四君子：梅 (`38`, `1花`)、蘭 (`39`, `2花`)、竹 (`40`, `3花`)、菊 (`41`, `4花`)，各 1 張
- **`TileId` (`u8`: `0..=143`，共 144 張實體牌)**：
  - 序數牌與字牌 (`kind in 0..=33`)：`tile_id = kind * 4 + copy_index` (`0..=135`，`copy_index in 0..=3`)。
  - 花牌 (`kind in 34..=41`)：`tile_id = 136 + (kind - 34)` (`136..=143`)。
  - 轉換公式：
    - `kind_of(tile_id)`: 若 `tile_id < 136` 則為 `tile_id / 4`，否則為 `34 + (tile_id - 136)`。
    - `is_flower(kind)`: `kind >= 34`。

## 2. 台灣 16 張麻將確定性狀態機

1. **座位與風位 (`SeatIndex: 0..=3`)**：
   - `0: 東 (East)`、`1: 南 (South)`、`2: 西 (West)`、`3: 北 (North)`，出牌與抓牌順序為逆時針 `0 -> 1 -> 2 -> 3 -> 0`。
2. **開局與補花 (`DEALING -> FLOWER_REPLACEMENT`)**：
   - 閒家起手 16 張，莊家起手 17 張（開門）。
   - 自莊家起依逆時針順序檢查手牌中的花牌（`kind >= 34`），亮出至花牌區並從牌尾（嶺上游標 `tail_cursor`）補牌；若補進花牌則繼續補，直到四家手牌皆無花牌，進入莊家首次出牌階段（`TURN_ACTION_OR_DISCARD`）。
   - 若補花過程湊齊 8 張花（「八仙過海」）或 7 張花且最後第 8 張花在別家（「七搶一」），可立即宣告花胡。
3. **摸打與槓補 (`TURN_DRAW -> TURN_ACTION_OR_DISCARD`)**：
   - 輪到玩家時從牌山正序游標 `head_cursor` 摸 1 張牌（若摸到花牌立即亮出並從 `tail_cursor` 補牌）。
   - 摸牌後（手牌數滿足 $3n+2$）可選擇：
     - **自摸 (`TSUMO`)**：手牌 + 副露滿足 5 面子 + 1 雀頭（或嚦咕嚦咕 8 對半）。
     - **暗槓 (`ANKAN`)**：手牌中 4 張相同 `TileKind`，移入副露並從 `tail_cursor` 補 1 張牌。
     - **加槓 (`KAKAN`)**：已碰出的刻子加上手牌第 4 張，觸發其餘三家**搶槓胡**檢查；無人搶槓則從 `tail_cursor` 補 1 張牌。
     - **宣告聽牌 (`MIGI` / `RIICHI`)**：鎖定手牌，後續摸牌若不能胡/暗槓則自動摸切。
     - **打牌 (`DISCARD`)**：打出一張暗牌進入自家牌海（River），手牌數回到 $3n+1$（從根源杜絕多牌或少牌相公）。
4. **攔胡與副露視窗 (`CLAIM_WINDOW`)**：
   - 玩家打出牌 `d` 後，計算其餘三家對 `d` 的合法動作（`RON` 放銃胡、`MINKAN` 明槓、`PON` 碰、下家 `CHII` 吃）。
   - 若無任何合法動作，直接輪到下家摸牌。
   - 若至少一家有合法動作，進入 `CLAIM_WINDOW`：收集所有具合法動作玩家的決策（`Claim` 或 `Pass`），全數收齊（或倒數逾時）後依優先序裁決：
     - **優先序**：`RON (胡) > MINKAN (明槓) / PON (碰) > CHII (吃)`。
     - **攔胡規則**：多人同時宣告 `RON` 時，預設採**逆時針最近順位者截胡（攔胡）**（可由 `RuleConfig.allowMultiRon` 切換一炮多響）。
   - **過水限制**：同巡內對可胡之牌選擇 `Pass`（或有更高動作卻放棄）者，在自己再次摸牌前進入「過水鎖定 (`furiten_temp`)」，不得胡他人打出的牌；放棄碰牌者同巡不得再碰同一種牌。
5. **鐵八墩流局 (`EXHAUSTIVE_DRAW`)**：
   - 牌山未摸牌數 `remaining_tiles == 16`（鐵八墩）時停止摸牌；最後一張打出且無人胡牌（河底撈魚）後即宣告流局（臭莊，莊家連莊 `streak + 1`）。

## 3. 台灣 16 張標準台數表 (`crates/mahjong-core/src/yaku.rs`)

結算金額公式：$\text{每家應付} = \text{底 (Base)} + \text{總台數 (Total Tai)} \times \text{台 (Point per Tai)}$。

| 分類 | 牌型 / 條件 | 台數 | 互斥 / 備註 |
|---|---|---|---|
| **莊家與風圈** | 莊家 | 1 台 | 東風局起莊；胡牌或流局連莊 |
| | 連 $N$ 拉 $N$ | $2N$ 台 | 連莊 $N$ 次時，加計 $2N$ 台（含莊家共 $2N+1$ 台） |
| | 圈風刻 / 門風刻 | 各 1 台 | 若同為東風圈東家，東風刻計 2 台（雙東） |
| **門清與自摸** | 門清 | 1 台 | 無吃、無碰、無明槓（暗槓仍算門清） |
| | 自摸 | 1 台 | 自己摸進胡牌張 |
| | 門清一摸三 | 3 台 | 門清 + 自摸合算 3 台（不另計門清 1 與自摸 1） |
| | 不求人 | 1 台 | 特殊附加或包含於門清一摸三（依房間設定，預設合入一摸三） |
| **花牌與三元** | 正花 | 各 1 台 | 東=1花(春/梅)、南=2花(夏/蘭)、西=3花(秋/竹)、北=4花(冬/菊) |
| | 花槓 (四季 / 四君子) | 2 台 | 集齊春夏秋冬或梅蘭竹菊（不再單計其中正花，計 2 台） |
| | 七搶一 / 八仙過海 | 8 台 | 特殊花胡 |
| | 三元刻 (中 / 發 / 白) | 各 1 台 | 刻子或槓子 |
| | 小三元 / 大三元 | 4 台 / 8 台 | 不另計中發白單刻台 |
| **聽牌與時機** | 獨聽 (邊張 / 嵌張 / 單吊) | 1 台 | 僅聽單一種牌且為邊三七、中洞或單騎 |
| | 聽牌宣告 (MIGI) / 天聽 | 2 台 / 8 台 | 宣告聽牌後鎖定手牌 |
| | 槓上開花 / 搶槓 / 海底撈月 / 河底撈魚 | 各 1 台 | 嶺上補牌自摸 / 搶加槓 / 最後一張自摸或放銃 |
| | 全求 | 2 台 | 5 組吃碰明槓露在外面，單吊最後一張由他人放銃（不計單吊 1 台） |
| | 天胡 / 地胡 / 人胡 | 16 / 16 / 8 台 | 莊家起手胡 / 閒家首巡自摸 / 首巡無副露放銃 |
| **手牌大牌** | 平胡 | 2 台 | 無字、無花、無刻子、有順子兩面聽、非自摸 |
| | 碰碰胡 | 4 台 | 5 組面子皆為刻子或槓子 |
| | 混一色 (湊一色) / 清一色 / 字一色 | 4 / 8 / 16 台 | 單一花色配字牌 / 純單一花色 / 全字牌 |
| | 三暗刻 / 四暗刻 / 五暗刻 | 2 / 5 / 8 台 | 手牌內暗刻（含暗槓；放銃完成的刻子不算暗刻） |
| | 嚦咕嚦咕 (八對半) | 8 台 | 7 個對子 + 1 個刻子（共 17 張，門清限定） |
| | 小四喜 / 大四喜 | 8 / 16 台 | 東南西北三刻一對 / 四刻（不另計圈風門風刻） |

## 4. P2P 防作弊連線協議 (`Co-Seeded Commit-Reveal`)

1. **搖骰承諾階段**：
   - `SEED_COMMIT`: `{ type: 'SEED_COMMIT', playerId, commitHash }`
   - `SEED_REVEAL`: `{ type: 'SEED_REVEAL', playerId, seedHex }`
   - 收齊 4 人 `seedHex` 後：`roundSeed = sha256(seed0 | seed1 | seed2 | seed3)`。
2. **牌山鎖定階段（Host 廣播）**：
   - `WALL_LOCKED`: `{ type: 'WALL_LOCKED', roundSeed, leafHashes: string[] /* 144 筆 SHA256(index|tileId|salt) */ }`
3. **摸牌私訊與公佈階段**：
   - `TILE_DRAWN_PRIVATE`（Host -> 摸牌者）: `{ type: 'TILE_DRAWN_PRIVATE', wallIndex, tileId, salt }`（摸牌者驗證 `sha256("${wallIndex}|${tileId}|${salt}") === leafHashes[wallIndex]`）。
   - `TILE_DRAWN_PUBLIC`（Host -> 全員）: `{ type: 'TILE_DRAWN_PUBLIC', playerId, wallIndex, flowerReveals: TileId[] }`。
4. **出牌與副露裁決階段**：
   - `PLAYER_ACTION`: `{ type: 'PLAYER_ACTION', playerId, action: PlayerActionCommand }`
   - `STATE_EVENT`: `{ type: 'STATE_EVENT', seq, event: TableDomainEvent, stateHash }`
5. **終局稽核階段**：
   - `ROUND_AUDIT`: `{ type: 'ROUND_AUDIT', hostSecret, fullWall: TileId[], salts: string[] }`（全體客機以 Wasm 重算驗證牌山未遭竄改）。

## 5. Subagent 派發與模組隔離守則

1. **跨切片契約唯一來源**：所有跨切片共用型別統一放在 [`src/shared/kernel/types.ts`](../src/shared/kernel/types.ts)，各 Slice 只透過自身的 `index.ts` 匯出公開介面。
2. **單一工作包邊界**：每個 Subagent 一次只負責 [`03-execution-plan.md`](./03-execution-plan.md) 中的一個 `WP-*`，嚴禁修改工作包目標檔案以外的切片，且回報前必須執行對應的驗收指令（`pnpm test:rust`、`pnpm test` 或 `pnpm build`）。
